auction starts, etc.) → Backend creates notification in DB\n3. **Socket emits** → Real-time notification sent to relevant users\n4. **Frontend receives** → Toast notification + dropdown update\n5. **User interacts** → Mark as read, clear, or navigate to auction\n\n### Notification Types:\n- **Global**: Sent to all connected users (auction starts/ends)\n- **Room-based**: Sent to users in specific auction rooms (new bids)\n- **Personal**: Sent to specific users (winner notifications, payment reminders)\n\n### Database Integration:\n- All notifications are stored in MongoDB\n- Supports read/unread status\n- Automatic cleanup of old notifications\n- Performance optimized with indexes\n\n## 🎯 Key Features\n\n### Backend:\n- ✅ Real-time Socket.IO integration\n- ✅ Database
